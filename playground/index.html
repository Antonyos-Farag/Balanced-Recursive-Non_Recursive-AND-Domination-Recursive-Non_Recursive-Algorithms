What each strategy says

The archived divide & conquer uses None as its "no dominator" marker, so on [null, null, 1] it reports nothing — the value null is a perfectly good dominator there. Bug B12.

Divide & conquer: the same array, recursively halved

Each node asks both halves for their majority, then counts a candidate over its own range only when it survived. Reading the tree is reading the proof: if a value dominates a range, it dominates at least one half.

          Measured on CPython 3.11 with the repository's own functions. The budget is
          1,000 frames total: every frame between you and the recursion is a
          character you cannot scan. That is why the repository's recursion is a
          translation (a loop for the outer call) rather than a decoration, and why
          run_deep runs in a thread with a big stack when the recursion must stay.
        

      


      

        
Mutate, recurse, undo

        

          The recursive scan has two spellings. Copying the frequency table per level is
          simple but pays 26 integers per frame; mutating one shared table and undoing the
          mutation afterwards is the classic backtracking shape and is measurably faster.

          Identical element-read counts in all three rows. The difference is what the
          machine does between the reads — which is why the repository measures both.
        

      

    

  


  
  

    

      

        
What this page is

        

          A single self-contained file that re-implements, in JavaScript, the algorithms
          this repository studies: the archived (buggy) loop, the repaired double loop,
          the pair scan, the Boyer–Moore vote, and the divide & conquer recursion.
          It is a companion: the Python versions are the source of truth, and
          the numbers quoted in the other tabs come from docs/traces/bench.txt.
